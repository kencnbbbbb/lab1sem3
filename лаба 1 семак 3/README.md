## Сборка и запуск

Нужны компилятор C++17, make; для второй реализации — Go 1.20 или новее. Для проверок интерфейса нужен Python 3, сторонние пакеты не нужны.

Из папки проекта:

```sh
make
./dbms --file data.txt --query 'TINSERT mytree 10 5 20 3 7 15'
./dbms --file data.txt --query 'PRINT mytree'
./dbms --file data.txt --query 'TCHECKCOMPLETE mytree'
./dbms --file data.txt --query 'TFIND mytree 7'
```

Go:

```sh
make go
./dbms-go --file data-go.txt --query 'TINSERT mytree 10 5 20 3 7 15'
./dbms-go --file data-go.txt --query 'PRINT mytree'
```

Программа выполняет **один запрос за запуск**. Если файл отсутствует, первый изменяющий запрос создаст его. Необязательно создавать контейнер отдельной командой: добавление в конец, голову или дерево создаёт отсутствующий контейнер. Чтение и удаление требуют существующий контейнер. Имена уникальны среди всех типов. `CREATE` выдаёт ошибку, если имя уже занято.

Значения массивов, списков, стека и очереди — строки без пробелов. Значения дерева — целые числа от −2147483648 до 2147483647; повторы разрешены. Индексы начинаются с нуля. Кавычки вокруг запроса обрабатывает командная оболочка; вложенные кавычки и значения с пробелами программа не разбирает.

Успешное изменение обычно не печатает ответ. `SPOP` и `QPOP` печатают удалённое значение. Поиск в списке возвращает индекс первого совпадения или `-1`; поиск в дереве и проверка полноты — `TRUE`/`FALSE`. Чтение пустой структуры печатает пустую строку, `PRINT` пустого дерева — `(empty)`.

## Команды

В таблицах `name` — имя структуры, `value` — значение, `key` — первое совпадение в списке. Несколько значений обрабатываются последовательно слева направо.

### Массив M

| Команда | Действие |
|---|---|
| `MCREATE name` | Создать пустой массив |
| `MPUSH name value [value ...]` | Добавить в конец |
| `MPUSHIDX name index value` | Вставить по индексу 0..длина |
| `MGET name index` | Прочитать элемент |
| `MDELIDX name index` | Удалить элемент |
| `MSETIDX name index value` | Заменить элемент |
| `MLENGTH name` | Получить длину |
| `MREAD name` | Прочитать весь массив |

### Списки F и L

Заменить `X` на `F` для односвязного или на `L` для двусвязного списка.

| Команда | Действие |
|---|---|
| `XCREATE name` | Создать пустой список |
| `XPUSH name value [value ...]` | Добавить в хвост |
| `XPUSHHEAD name value [value ...]` | Последовательно добавить в голову |
| `XPUSHBEFORE name key value` | Вставить перед первым key |
| `XPUSHAFTER name key value` | Вставить после первого key |
| `XPOP name` | Удалить хвост |
| `XPOPHEAD name` | Удалить голову |
| `XPOPBEFORE name key` | Удалить элемент перед первым key |
| `XPOPAFTER name key` | Удалить элемент после первого key |
| `XDELVAL name value` | Удалить первое совпадение |
| `XFINDVAL name value` | Найти индекс первого совпадения |
| `XREADHT name` | Прочитать от головы к хвосту |
| `XREADTH name` | Прочитать от хвоста к голове |

Если ключ или требуемый сосед отсутствует, операция над списком ничего не меняет. Удаление из пустого списка также ничего не меняет. Например, `FPUSHHEAD f a b` сначала добавляет a, затем b, поэтому результат — `b a`.

### Стек, очередь, дерево

| Команда | Действие |
|---|---|
| `SCREATE name`, `QCREATE name`, `TCREATE name` | Создать пустую структуру |
| `SPUSH name value [value ...]` | Добавить в стек |
| `SPOP name` | Прочитать и удалить вершину |
| `SREAD name` | Прочитать стек от вершины к основанию |
| `QPUSH name value [value ...]` | Добавить в хвост очереди |
| `QPOP name` | Прочитать и удалить голову |
| `QREAD name` | Прочитать от головы к хвосту |
| `TINSERT name number [number ...]` | Добавить по уровням слева направо |
| `TFIND name number` | Проверить наличие значения |
| `TREAD name` | Обход дерева в ширину |
| `TCHECKCOMPLETE name` | Проверить свойство Complete |
| `PRINT name` | Показать любую структуру; дерево — с путями к узлам |

Для совместимости: `MDEL` = `MDELIDX`, `MSET` = `MSETIDX`, `FGET` = `FREADHT`, `LGET` = `LREADHT`, `TGET` и `ISMEMBER` = `TFIND`, `TCHECK` = `TCHECKCOMPLETE`.

**Удаления из дерева нет:** по заданию для Complete Binary Tree оно заменяется проверкой полноты. Команды `TDEL`, `TDELETE` и `TCHECKAVL` не поддерживаются.

## Файл данных

```text
Array arr 10 20 30
OneLinkedList forward a b c
LinkedList double x y z
Stack stack bottom middle top
Queue queue first second third
Tree mytree 10 5 20 3 7 15
```

Одна структура — одна строка: тип, имя, значения. У пустой структуры только тип и имя. Стек сохраняется от основания к вершине, очередь — от головы к хвосту, дерево — по уровням слева направо. Такая запись сохраняет форму Complete Binary Tree.

Файл читается перед запросом и сохраняется после изменяющих команд через временный файл и переименование. Запросы чтения не перезаписывают файл. Неверный запрос или повреждённая строка дают ненулевой код завершения и сообщение в stderr; исходный файл остаётся прежним. Изменяющая команда списка без найденного ключа может перезаписать эквивалентное состояние.

Два экземпляра программы не следует запускать одновременно с одним файлом: блокировки не реализованы. Обычный текстовый формат дерева представляет только Complete-форму; отрицательные случаи проверки создаются напрямую в модульных тестах.

В C++ у массива сохранено ограничение примера: не более 65536 элементов. В Go отдельного такого ограничения нет. Текстовый сканер Go допускает строку файла до 16 МиБ. Данные с пробелами внутри значений, разные числовые типы и интерактивный режим не входят в этот интерфейс.

```sh

```

Каждый интерфейс проходит 844 проверки. В каждом запросе программа запускается заново: это одновременно проверяет сохранение и загрузку. Дополнительно проверяются корректные и некорректные формы дерева. Файлы `examples/*.txt` можно использовать вручную, предварительно сделав копию для изменяющих запросов.
